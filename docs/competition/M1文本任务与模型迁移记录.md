## 文本任务链路

- 提交前冻结 `textSnapshot` v1：模型、完整输入、最大输出 token、温度与 topP。原始快照保留在结果记录中，执行时不读取新默认值，也不采用 MQ 消息中的文本替换输入。
- `PARSE_TEXT` 直接在提交时建立的 Job 上执行并记录结果、用量和费用字段；不再另建一个 `TEXT_GENERATION` 子 Job。
- 参数或供应商配置不合法时，不创建 Job、不投递消息。消费时再次验证保存快照；缺少快照、版本不符、模型不匹配的待执行任务失败并要求重新提交，不补用新默认值。
- 消息中的用户和项目必须与保存任务一致。归属不匹配的消息被拒绝，不能修改其他用户任务状态。
- 数据库条件更新只允许一个消费者将同一 Job 从 `PENDING` 领取为 `RUNNING`。重复投递、正在执行和已结束任务均不再次生成或再次调用计费服务。这是同一 Job ID 的去重，不是不同新请求之间的幂等。
- 取消后的晚到响应保留调用结果、请求 ID、用量/费用或执行错误用于核对，任务仍为 `CANCELED`，不改回成功。已经结束的成功/失败任务不会被迟到校验覆盖。
- 取消接口仅原子更新仍为 `PENDING/RUNNING` 的所属任务，不写回旧实体；即使先读到执行中、随后生成已完成，也不能覆盖结果和审计信息。

此路径当前只保存模型文本结果；结构化分镜、角色/场景入库属于后续创作模块，不能将本批称为完整分镜生成闭环。

## 模型目录与增量迁移

新增文本注册表，将目录代码、真实 API ID、供应商字段分开。用户模型目录过滤旧模型、供应商错误及当前未配置能力；管理员创建、编辑或启用语言模型时使用相同校验。旧记录仍可查看或停用；不能重新启用旧文本调用。类型大小写和首尾空白不能绕过检查。

新增 `V33__stage_official_text_models.sql`，没有修改历史 Flyway 文件：

1. 停用已有语言模型，保留原记录及历史使用数据。
2. 准备三项官方文本模型记录，均保持 `enabled=0`；不把接口文档可读当成账户实测通过。
3. 停用现有文本积分定价规则，按已确认的参赛免费方向继续改造；不编造供应商价格。图片、视频配置仍留待其替换阶段处理。

V33 仅在测试用内存数据库执行，未连接或迁移本机 MySQL。前端硬编码默认值、浏览器缓存及管理端展示仍需同步处理。

## 新发现与剩余发布阻塞项

用户已确认参赛免费、记录真实模型用量并限制预算。`ChargingService.charge` 的既有实现硬编码返回测试免费及虚拟余额，真实扣费逻辑处于注释中。本批没有恢复收费。测试验证的是计费方法的调用次数，**不能据此宣称实际扣积分、账务对账或供应商成本记录已完成**。下一批需去掉虚拟余额误导、落实免费模式，并补充预算限制；未知供应商用量仍保持未知，不估算为零成本。

进程在领取后崩溃时，`RUNNING` 不会自动重投，以免重复消耗额度；需先核对供应商受理情况。受理不明的“待核对”状态、失败/取消后的账务规则、同步文本事务失败留痕及既有 `@Async` 自调用行为仍需补齐。新供应商继续保持默认关闭。
