## 安装和启动原则

安装命令与启动说明保存在环境的 Install script / Start skill 中。工具、依赖缓存和运行配置均使用云端独立目录，不依赖本机 `.superpowers` 或原工程服务。无需为代码构建和自动化测试提供真实模型密钥。

公网保持包管理器域名范围，必要安装通过逐项联网批准运行；不启用完全访问权限，不放开 Docker socket。普通命令沙箱内的代理拒绝不能直接解释为整个环境离线：本次通过受支持的联网批准请求验证了官方 npm registry 的 HTTP 200。

云端默认只有 Java 21、Node 24，且用户没有 apt/dpkg 系统写权限。项目字节码目标仍为 Java 17；若使用 Java 21 进行构建，应记录实际运行版本，不将其称作已验证的 JDK 17 环境。Maven 等工具可采用官方发行包安装到用户目录。数据库与队列必须使用云端独立服务或经授权配置的开发服务。

前端冻结安装后，若 pnpm 自动同步运行时导致重装，可用当前 Node 直接执行已安装工具，避免修改包清单或锁文件：

```sh
cd frontend # 管理端替换为 frontend-admin
node node_modules/vitest/vitest.mjs run
node node_modules/typescript/bin/tsc -b --noEmit
node node_modules/typescript/bin/tsc -b
node node_modules/vite/bin/vite.js build
```

## 密钥与数据

不复制本机 API 密钥、账号会话、数据库或存储。云端演示配置使用新生成的随机 JWT、数据库及管理员凭据，保存在云端私有配置中，不输出到文档或源码。真实 DeepSeek、MiMo、Firecrawl 凭据须由用户在云端单独配置；图片/视频仍保持未开放。

环境发布前需核对实际通过的测试、构建及服务就绪证据。保存草稿不等于验证通过，未验证的运行依赖不得标为已完成。
