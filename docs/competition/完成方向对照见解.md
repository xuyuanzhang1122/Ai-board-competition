## 三处偏移风险

### 1. 供应商目标缩了，注释还指向旧模型

初想写的是四段能力：文字 MiMo 与 DeepSeek，图片 Seedream 与可灵，视频 Seedance 与可灵。火山方舟因余额门槛被划掉后仍留在计划第六节。现状是只有 DeepSeek / MiMo 文字真接入。可灵图片只在应用外探测过一张，视频按既有边界不测，应用内没有任何官方媒体适配器。

危险的不是“还没接上”，而是下一刀可能按过期注释接错供应商。这些注释仍把旧世界写成可用模型：

- `backend/.../service/AiImageService.java` 示例使用 `doubao-seedream-4-5-251128`
- `backend/.../dto/ai/BatchGenerateRequest.java` 同样示例
- `backend/.../service/BatchGenerationService.java` 注释中的同一模型 ID
- `backend/.../dto/toolbox/ToolboxGenerateRequest.java` 写着 `GeekNow` 图片白名单和 `sudashuiapi Seedance 2.0`

`docs/FILE_CATALOG.md` 的 Client 一节仍把 `ImageGenerationRouter`、`GeeknowClient`、`Sub2ApiImageClient`、`SudashuiVideoClient` 写成现行实现。那一节已经不能当接入说明。历史计划正文里的“当前依赖 Geeknow”是规划时点，不应再被读成 `e759193` 的运行事实。

若继续做媒体，实现目标应是已经探过的可灵图片，外加预算与任务恢复。不要按上述注释去接 Seedream、Seedance 或任何旧客户端。火山方舟保持未开通、不启用。视频维持不测。未授权前的桩不能记成真实成功。

### 2. 完成定义从“能演示的初赛闭环”滑向“平台还没做完”

计划 1.3 的初赛成功标准包括：新人能走完输入到素材导出、至少一份真实运行案例写清 AI 与人工各做了什么、全部调用走新供应商、有对照才谈效率。状态总表把进入下一关写成官方媒体适配、批量冲突、外网读页补验、正式知识包。这些都在原计划内，本身不是跑偏。

跑偏的是优先级。通知中的作品提交日写的是 2026-11-30（计划写明学校内部截止须另行核实，本轮也没有重核赛方通知）。今天若继续只补协议和编辑器边角，而不收一份可讲述的案例，M5 会在工程清单全部打勾之前到来。

已有文字案例不能直接升格：

- 烟台三组没有图片或视频，画面提示词仍是文字。
- [局部重生成与右侧入口验收](./局部重生成与右侧入口验收记录.md) 使用的是虚构灯塔样例，该记录自己写明不能称作本土正式完整案例。
- R11 仍无相同任务的人工对照或非团队成员试用，不能写提升百分比。

因此“媒体适配”可以做，但不应成为初赛冻结的唯一前置。先把已有八仙或戚继光文字过程收成演示材料：输入、人工改了什么、六 Sheet Excel、缺图缺视频如实列出。录屏和两页说明按赛道三细则准备，不把 ZIP 或 Excel 说成一键成片。

### 3. 比赛叙事是文旅工作台，打开仍是旧工作室的壳

功能开关已经把充值挡住，这是对的。壳没有换：首页仍是项目列表，主编辑器仍是原分镜台；支付、钱包、邀请、短信和微信登录的代码还在，只是用户走不到充值。评委从首页进入时，先看到的不是“蓬莱创作工作台”。

这不要求初赛重写信息架构。演示路径应固定为：文字创作或头脑风暴 → 确认 → 落笔生辉 → 建项目 → 导出，并在说明里写明首页和编辑器是承接原工程的创作台。不要在初赛再打开钱包、邀请或微信支付。

`docs/FILE_CATALOG.md` 与源码不一致，会让后续协作者按旧客户端继续改。目录应改成“历史客户端已退出，媒体当前由 `UnavailableMediaProvider` 拒绝”，本篇不在同一次改动里重写整份目录，避免把见解和大规模文档修订捆在一起。
