## 可复用的运行入口

隔离依赖仍使用仓库提供的命令：

```bash
docker compose --env-file infra/competition/.env.local -f infra/competition/compose.yaml up -d
```

本轮为隔离实例生成独立随机数据库、队列及管理员密码，保存在忽略文件中；JWT 也独立生成。后端显式禁用默认 dotenv 合并，仅加载本任务配置，避免意外继承旧项目连接。

在仓库根目录启动后端：

```bash
APP_DOTENV_ENABLED=false /tmp/competition-jdk/bin/java \
  -jar backend/target/ai-story-studio-server-0.0.1-SNAPSHOT.jar \
  --spring.config.location=file:/workspace/Ai-board-competition/credentials/runtime/application.properties
```

前端分别在 `frontend/` 和 `frontend-admin/` 中启动：

```bash
node node_modules/vite/bin/vite.js --config vite.cloud.local.ts
```

两个本机 Vite 配置关闭 envDir、使用严格独立端口，将 `/api` 和 `/uploads` 代理到 18080。它们通过本机 `.git/info/exclude` 排除，没有修改版本化的开发端口。

本环境最初只有 Java 21 运行时，没有 javac。已从 Adoptium 获取 JDK 17 并校验其官方 SHA-256。Maven 使用继承的云代理地址生成本机 settings，并通过 `-Djavax.net.ssl.trustStore=/etc/ssl/certs/java/cacerts` 信任环境 CA；未关闭 TLS 验证。

当前 pnpm 11 不再读取 package.json 中旧 pnpm 构建许可配置，用户端 `pnpm build` 的隐式安装因此失败。本轮直接运行已有依赖的 TypeScript、Vite 和 Vitest 入口完成同等构建/测试，没有修改锁文件或放宽构建脚本许可。

根盘仅约 8 GB，拉取依赖容器后曾耗尽空间，首次后端启动因无法创建上传目录失败。已将前端依赖及 Maven 缓存转移到独立 `/tmp` 盘并保留软链接，重启成功。JDK、Maven 和这些缓存依赖当前临时盘；环境重建需要重新准备，不能把它们当作冻结镜像。根盘余量仍有限，媒体转存前需扩容或配置独立存储。
