## 服务端行为

V39 新增简报/剧本/分镜草稿、生成运行、人工事件、版本化提示词表，以及分镜扩展元数据字段。

生成先创建任务和冻结输入，数据库轮询器负责执行，浏览器仅提交和查询。运行保存输入版本、模型、任务 ID、提示词版本、原始输出和错误。候选必须显式采用；剧本与分镜必须显式确认。修改简报或剧本后，旧分镜保留并标记过期。

- 请求 UUID 用于创建和生成的幂等；同 UUID 不同输入拒绝。
- 并发创建同 UUID 回读同一草稿；每份草稿最多一个活动生成。
- 编辑使用版本检查；晚到候选不能覆盖后续人工修改。
- 服务重启保留 PENDING 工作；RUNNING 未知受理转待核对失败，不自动重发。
- 分镜必须是严格 JSON：稳定 ID、资产类型与引用、连续序号、1–20 镜、15–90 秒目标、总时长误差最多 10%。
- 手工保存的整数也严格解析，小数不会被悄悄截为整数。
- 无效、截断输出不能采用或建项目；原始部分输出保留可查看。
- 项目、角色、场景、道具、镜头与绑定在同一事务入库，失败整体回滚。
- 建项目后是独立快照；继续修改创作不会自动覆盖已有项目。

来源由创作者提供，包含网址与授权说明；本轮没有实现来源事实审核，也没有将“来源存在”表述为“内容已核验”。

## Excel 与权限

导出包含“分镜、出场人物、场景、道具、来源与复核、创作记录”六个 Sheet。分镜前六列保持“序号、剧本、出场人物、场景、道具、分镜图”，扩展列含时长、景别、运镜、旁白、对白、提示词和稳定 ID。完整 JSON 分块写入，避免 Excel 单元格 32767 字符限制。

已核对 4 条镜头记录、人工修改、参赛品牌及声明，公式单元格为 0。旧 Excel 导入器只承诺兼容前六列和资产，不能将此导出描述为扩展字段的完整 Excel 往返。完整结构以服务端创作记录为准。

另一测试账号对创作读取、保存、导出、项目镜头读取均被拒绝；返回业务错误而无创作数据。旧页签在另一页签退出后立即跳登录，新账号不能看到原账号草稿、项目快照或人工修改。验收后已恢复主验收账号。

## 审查与回归修复

独立审查先后发现并复现：截断输出遗失、长 JSON 导出失败、JSON 尾部与浮点隐式转换、并发创建幂等响应、跨页签请求身份混用、远端版本轮询失真。对应问题已补回归并修复。

前端每次创作请求绑定捕获的账号和 token，实际 adapter 发包前及返回时再次核验；storage 事件清除原账号资料，迟到 profile 或旧 token 的 401 不覆盖/注销新账号。轮询对干净页面采纳新版本；有本机编辑时保留编辑正文和基准版本，同时显示远端冲突。候选采用、确认和导出不能暗用另一个版本。

## Kling 图片追加授权与限额结果

用户追加授权：Kling 图片可测试，总量不超过 100 积分，视频不测试。

依据官方[图片计费](https://www.klingai.com/document-api/pricing/base/image.md)、[中国地区鉴权](https://www.klingai.com/document-api/api/get-started/authentication.md)和[图片生成接口](https://kling.ai/document-api/api/image/3-0-omni/image-generation.md)，采用中国地区官方域名、新 API Key 鉴权、`kling-v3`、1K、16:9、`n=1`。

- 创建任务仅 1 次 POST，外部请求 ID 在提交前保存。
- 按官方每张 8 积分预留；任务 `941320505670774858` 成功返回一张 1360×768 图片。
- 上游 `final_unit_deduction` 为 `8`，实际消耗 8 / 100 积分。
- 查询曾遇到一次 TLS 连接中断，仅重试读取原任务，未重发生成。
- 图片已在浏览器打开核对，截图与受限探测账本保存在本机忽略目录。

这次是独立接口探测；应用内图片模型目录、持久媒体适配与生成入口尚未开放。没有测试视频。

## 范围决策与后续

本轮按用户优先级先交付文字纵向闭环，未把整个 M2/M3 标为完成。知识资料审核后台、外部资料检索、完整提示词管理界面、多个大纲方向选择、局部镜头重生成与应用内媒体接入仍需后续建设。

手工整数隐式转换虽被审查列为 minor，本轮按“会悄悄改变人工时长”升级修复；代价是小数或数字字符串输入需要改为整数后提交，符合当前契约。

唯一延期的实现优化项：草稿列表加载每份草稿的运行历史，存在 N+1 查询，当前上限 100 份。后续在更大数据量部署前改为摘要与分页；未影响此次功能验收。
