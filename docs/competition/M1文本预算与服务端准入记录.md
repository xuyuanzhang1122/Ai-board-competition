## 服务端准入

官方文本适配器在请求校验及实际调用时查询模型目录，校验代码、启用标记、语言类型和供应商。数据库缺行、停用或配置不匹配均拒绝，覆盖文本任务与直接剧本调用；前端筛选不再是唯一防线。管理员的配置校验与执行校验分开，合法模型可从停用状态启用，停用操作不受价格配置限制。

供应商开关、凭据、官方地址和已核验预算价格缺一不可。候选模型仍只有 `deepseek-flash`、`deepseek-v4-pro`、`mimo-v2.6-pro`，没有旧上游回退。

## 额度预留与调用审计

新增 V34，不修改历史迁移及钱包数据。`generation_budget_accounts` 只有一个供当前文本共用的账户，初始上限 20.000000 元；`generation_budget_reservations` 保存每次调用的归属、模型、不可变价格快照、上界、状态和真实返回用量。

预留金额按以下配置上界计算，向上取至小数点后六位：

```text
模型最大计费输入 token 数 × 输入人民币单价 / 1,000,000
  + 本次最大输出 token 数 × 输出人民币单价 / 1,000,000
```

这里的输入上界必须是经核验的完整模型计费限制，不能填本次预计输入量；输入价格须覆盖可能出现的最高适用输入费率。它不依赖字符数估算，也不以积分或缺失用量的零代替人民币成本。实际价格、计费边界和响应模型标识仍需核验，本批没有填入任何真实价格。

预留采用独立 `REQUIRES_NEW` 短事务：同一账户的条件更新与审计插入一起提交，确认提交后才发 HTTP。多个请求竞争同一上限；业务 Job 随后回滚，也不能撤回已经可能产生费用的预留。网络调用期间不持有预算事务。

- `RESERVED`：已预留，尚无完整结果；进程中断后保留，不自动重投。
- `SUCCEEDED`：已保存模型、请求 ID 及实际输入/输出/总 token；仍保留全部预留上界。
- `REVIEW_REQUIRED`：网络或解析异常、缺失用量、模型变化、用量越界或不一致、审计异常等，需要人工核对；保留预留并冻结后续新预留。

字段缺失与字段存在但非法分开处理：只有总 token 字段缺失且输入/输出均有效时才允许求和；负数、小数、字符串和溢出总数不补成正常用量。截断、空内容等失败响应先提取已有请求 ID 和可验证用量，再以待核对状态保存；不能因为生成内容不完整而抹掉已取得的核账数据。有效文本与预算审核状态分开，文本可留用也不等于调用账务已核验。

成功也不自动退回“多预留”的部分。`reserved_cny` 表示保守占用，**不是实际已消费账单**；`actual_cost_cny` 保持空值。供应商忽略参数、调价或不符合已核验计费上界的行为，需要供应商侧账单和额度核对，不能宣称本功能能直接限制供应商计费系统。

任务元数据保存 `budgetReservationId`、`inputTokens` 和 `outputTokens`，可与独立审计记录关联。供应商返回不完整用量时不编造数值。用户积分策略继续为参赛免费。

## 启用配置及查询边界

新增配置命名空间 `competition.text-budget`，默认 `enabled=false`、`quotes={}`。每个候选模型配置必须同时提供：

| 字段 | 含义 |
| --- | --- |
| `revision` | 核验版本，最长 128 字符 |
| `verified-at` | UTC 核验时间，不允许未来时间；有效期 7 天 |
| `reference` | 核验依据，最长 512 字符，不能放密钥 |
| `response-model` | 经最小调用核验的实际响应模型标识 |
| `max-billed-input-tokens` | 完整输入计费上界，1 至 10,000,000 |
| `input-cny-per-million` | 最高适用输入费率，正数，最多六位小数 |
| `output-cny-per-million` | 输出费率，正数，最多六位小数 |

输出上限由本次请求冻结参数决定，目前限制在 1 至 32768。缺失、过期或非法配置拒绝调用，也不能仅靠管理员目录开关启用。测试中的价格全部是离线合成数据，不能复制为真实账户配置。

只读接口 `GET /api/admin/generation-budget` 返回上限、已预留、剩余额度、冻结原因和未核对数量；沿用管理员 JWT 边界，普通用户和匿名请求不能读取。没有自动退款、解除冻结或提额接口。历史人工核对和真实价格确认前，不执行清空记录或重置预算。

角色边界改为依据 Spring 实际匹配的 Handler 路由，而不是原始 URI 拼写；带矩阵参数或编码的管理路径同样拒绝普通用户。正常用户路径仍拒绝管理员 token。摘要中的剩余金额是账本差额，不表示模型已开放；冻结或配置关闭时不能据此继续调用。

## 验证证据与范围

- 相关 Java 测试最新完整确认 98 项通过；Python 检查 11 项通过。
- H2 MySQL 兼容模式执行生产 V34，验证 20 元竞争上限、审计插入失败回滚、业务回滚保留预留及完成记录、服务对象重建后的持久记录、重复结果保护与待核对冻结。
- 实际预算策略及生产 SQL 与模拟 HTTP 组合验证先提交预留后 POST、额度耗尽及网络不确定后不再 POST。管理员接口通过实际 JWT 拦截器和模拟身份验证只读边界。未启动 Spring Boot 应用。
- 独立只读审查发现的管理路径绕过、非法总用量被重算、截断响应丢审计三项重要问题，均以失败测试复现并修复；补充矩阵/编码路径、普通用户路径保持隔离、四类非法总用量和截断响应的生产 SQL 回归。最终完整套件恢复通过，没有将修复仅停留在静态推断。
- 首次完整回归中旧图片本地模拟测试出现一次 404/响应提取错误；该类单独复测 5 项通过，同一完整套件再次确认通过，修复审查问题后的最终 98 项亦通过。未改旧图片实现，未复现根因，不将其描述为已修复。

本批没有读取真实密钥、连接本机数据库或 RabbitMQ，也没有付费模型调用。H2 和模拟 HTTP 不替代 MySQL/Flyway 实际部署、供应商账户价格/计费上界核验与真实小额调用。前端本批未改动，不重复宣称浏览器验收已通过。

预算控制当前覆盖已替换的官方文本路径；旧图片/视频尚未接入，必须在全部上游替换时接入同一账户后才能开启。同步文本失败留痕和既有 `@Async` 自调用已在后续[文本调度与失败留痕记录](./M1文本调度与失败留痕记录.md)中处理；跨请求幂等和人工核对流程仍需继续处理。M0/M1 的阶段出口尚未满足。
