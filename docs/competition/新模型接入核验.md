# 新模型接入核验

核验日期：2026-10-13。本文区分官方文档证据与账户实测；尚未发起模型调用，费用为零。

## 已取得的接口证据

| 供应商 | 文档确认的接口 | 拟核验 API 模型 ID | 当前限制 |
|---|---|---|---|
| MiMo | OpenAI 兼容协议，按量入口 `https://api.xiaomimimo.com/v1`，Chat Completions | `mimo-v2.6-pro` | API Key 与 Token Plan 使用不同入口，须确认凭据类型；未验证账户可用性 |
| DeepSeek | `POST https://api.deepseek.com/chat/completions` | `deepseek-flash` | 不能直接沿用旧配置中的显示名/别名；未验证账户可用性 |
| 可灵 | 原规划中的图片文档 URL 目前仅抓到标题 | 待控制台/完整接口文档确认 | 不根据页面标题推断鉴权、参数和图片/视频能力 |
| 火山方舟 | 暂未进行账户核验 | 待开通后确认 | 用户确认尚未开通，暂不启用 |

MiMo 的首次调用文档给出 `mimo-v2.6-pro` 示例及 `max_completion_tokens` 参数；按量与订阅凭据应使用各自匹配的端点，不能自动互换。依据：[MiMo 首次调用](https://mimo.mi.com/docs/zh-CN/quick-start/summary/first-api-call)。

DeepSeek 当前接口列出 `deepseek-flash`、`deepseek-v4-pro`，支持消息与函数工具定义；可使用 `thinking.type=disabled` 做最小文本核验，并显式限制 `max_tokens`，避免采用默认输出上限。依据：[DeepSeek Chat Completions](https://api-docs.deepseek.com/zh-cn/api/create-chat-completion)。

抓取原可灵页面未取得可实现的请求/响应正文，因此仍是接入待核项。来源：[可灵图片接口页面](https://www.klingai.com/document-api/api/image/3-0-omni/image-generation)。缓存位于已忽略的 `.firecrawl/`，不是生产配置或实测证据。

## 凭据就位后的最小验证顺序

1. 确认文件路径、供应商与凭据类型；不输出、提交或记录密钥。
2. 先核验 MiMo/DeepSeek 的小额文本请求：短输入、限制输出、非流式、关闭可配置的思考模式；不自动重试。
3. 记录实际响应模型、状态、请求 ID、耗时、用量，以及是否支持工具调用；失败记录仅保留脱敏错误，不保留请求头。
4. 明确可灵完整接口及计费后，再选最少图片/最短视频任务，分别检查提交和查询；受理结果不明时不重复提交。
5. 首轮按 20 元预算上限安排；价格与账户额度未核实前，不将数量或估算写为已验证成本。

文档可读、账户已开通、一次成功调用、产品路径已接通是不同状态。只有真实验证通过的模型才能加入可启用能力矩阵；目前没有模型达到此条件。
