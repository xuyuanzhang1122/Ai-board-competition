## 一、项目定位与成功标准

### 1.1 建议定位

面向蓬莱景区、新媒体运营人员及校园文旅创作团队，提供一个将本土资料转化为**可核验、可编辑、可追溯的短视频故事与分镜，并衔接素材生成**的创作工作台。

核心业务痛点：资料散、通用 AI 容易混淆神话与事实、剧本到分镜存在重复整理、人工修改过程难以证明、图片和视频生成缺少统一管理。

初赛聚焦一个明确环节：**从传播需求到可执行分镜及生成素材**。文旅成片是成果案例；可交互工具及其业务改善是赛道三的主要展示对象。

### 1.2 端到端流程

```mermaid
flowchart LR
    A[资料与授权来源] --> B[受众·渠道·传播目标]
    B --> C[头脑风暴：检索与故事大纲]
    C --> D[人工确认大纲版本]
    D --> E[落笔生辉：结构化剧本与分镜]
    E --> F[事实·来源·格式复核]
    F --> G[人工修改与确认留痕]
    G --> H[创建项目·生成图像与视频片段]
    H --> I[导出分镜·素材·过程记录]
    I --> J[案例对比与传播成果展示]
```

复核与人工编辑不是只在末尾发生：大纲、分镜和生成素材均允许回退修改；上游版本变更时，应提示下游成果可能过期。

### 1.3 初赛成功标准

- 一个新使用者可以用预置资料完成输入、生成大纲、修改确认、生成分镜、导入项目、生成素材及导出。
- 每个关键事实可追到来源，神话传说和创作演绎有明确标签；资料不足时能暂停并要求补充。
- 至少保存一个完整真实运行案例，能够说明 AI 做了什么、人工改了什么、为何修改。
- 所有模型调用均通过新的指定供应商；旧供应商不可通过历史配置、直接请求或异步任务继续调用。
- 通过相同任务的对照记录证明效率或质量变化；没有实测数据时只陈述价值预期。

决赛交付包括完整可交互版本、技术说明、至少三个覆盖典型/复杂/边界输入的完整案例、一页使用说明和三分钟以内的演示视频。技术说明需覆盖调用逻辑与提示词、本土场景模块化、人机协作、业务价值，并附关键提示词迭代记录。上述材料清单由[赛道三细则](https://finance.dzwww.com/zt/2026ai/sdsz/202609/t20260928_18161132.htm)支持。

## 三、现有项目可复用能力与缺口

以下结论来自静态源码阅读，未启动应用复现全部交互，也未执行真实付费模型调用。

| 能力 | 当前证据 | 结论 |
|---|---|---|
| 项目、角色、场景、道具、分镜管理 | 既有 service、editor 与数据库迁移 | 沿用数据与编辑器主体 |
| Excel 导入 | `ImportServiceImpl.java` | 复用解析规则，但抽出共享入库逻辑 |
| 模型管理 | `AiModel.java`、管理端 `ModelConfig.tsx` | 有模型列表，仍需补能力参数与新上游适配 |
| 图片渠道路由 | `ImageGenerationRouter.java` | 目前按旧模型分流且返回类型依赖旧客户端，必须改为中立接口 |
| 文本调用 | `AiTextService.java` | 直接依赖 `GeeknowClient`，需要替换 |
| 视频提交与轮询 | `AiVideoService.java`、`AsyncVideoTaskService.java` | 直接依赖 `SudashuiVideoClient`，提交和查询需一起替换 |
| 提示词模板 | `PromptTemplateServiceImpl.java` | 有系统/用户模板 CRUD；不是完整的管理员发布、版本锁定、差异对比体系 |
| 硬编码提示词 | `ShotServiceImpl.java` 等 | 需清点并迁入可版本化管理的模板 |
| 角色/场景/道具右侧编辑 | `useShotAssetBindings.ts`、`RightPanelManager.tsx` | 已有面板路径，先回归验证再修缺口 |
| 分镜图/视频单项生成 | `StoryboardRow.tsx`、`EditorPage.tsx` | 当前优先走生成弹窗，与希望统一到右侧的交互不符 |
| 多道具展示 | `PropBindingsCell.tsx` | 当前网格、前三项及数量标签；未实现参考图中的叠放展开 |
| 项目导出 | `ExportServiceImpl.java` | 主要打包素材 ZIP，没有据此确认自动剪辑合成完整成片 |

现有技术栈可继续使用：Java 17 / Spring Boot / MySQL / Redis / RabbitMQ，用户端和管理端为 React + TypeScript。初赛不建议为 Agent 整体重写后端或新增一套微服务体系。

当前仓库存在未跟踪的 `backend/src/main/resources/application.properties`。后续实施应保留并由配置负责人核对，不覆盖、不把密钥提交到仓库。本文未读取该文件内容。

## 四、方案比较与推荐

全部方案均必须遵守“彻底替换旧上游”，差异只在创作流程的实现方式。

| 方案 | 优点 | 主要问题 | 建议 |
|---|---|---|---|
| A. 新上游 + 固定表单/模板生成 | 实现量小，容易跑通 | 对复杂输入和工具调度能力有限，难充分体现原设想的 Agent | 可作进度不足时的功能缩减，但应如实称为工作流 |
| B. 新上游 + 受控创作 Agent + 既有编辑器 | 兼顾可交互性、工具使用、人工干预与可追溯 | 需实现任务状态、工具边界和结构校验 | **推荐，作为本计划基线** |
| C. 新上游 + 任意脚本沙箱 + 通用多领域平台 | 扩展空间大 | 沙箱、文件系统、网络、恢复和权限成本高，偏离初赛核心 | 延后，必须由真实需求证明必要性 |

推荐方案中，模型可在受限步骤中选择检索资料、请求补充信息、编写和修订草稿；工作流控制可调用的工具、步骤上限和人工确认点。它不只是聊天窗口，也不要求模型获得任意 Shell 执行权。

## 六、强制替换全部模型上游

### 6.1 目标与边界

原设想中的新供应商范围为：小米 MiMo、DeepSeek、火山方舟、可灵。文本、图片、视频均纳入统一后端入口。显示名称、供应商、真实 API 模型 ID 分开管理，不用界面名称直接调用 API。

**替换不是仅修改管理端的模型列表。必须同时完成：**

1. 删除旧供应商专属客户端及运行期引用，替换受其绑定的响应 DTO 和错误类型。
2. 清理同步调用、异步提交、轮询、结果下载、重试、批量任务、工具箱及分镜解析路径。
3. 清理后端默认值、前端硬编码、缓存偏好、环境配置样例、部署配置及管理端选项。
4. 使用新的增量迁移清理/停用既有数据库中的旧可调用配置；不修改已执行的历史 Flyway 脚本。
5. 旧项目中的模型选择必须显式重新映射或提示重新选择；旧缓存不能恢复成可用配置。
6. 旧上游在途任务切换前暂停新提交并完成状态核对。未能完成的任务按现有账务规则对账后终止或标为待处理，不能让旧 MQ 消费继续访问原接口。
7. 历史素材、历史任务和计费记录作为证据保留，不因移除旧服务而删除；不允许从历史记录一键重跑旧模型。

允许分批开发适配器，但**发布必须一次满足全部替换门槛**。没有新供应商可用时，明确返回该能力暂不可用；不得静默回退到旧上游。代码回滚也必须保持旧上游禁用，不能把故障回滚当作恢复旧供应商的理由。

### 6.3 统一接口设计

复用现有 Job、MQ 和资产版本体系，在其下增加供应商适配层，不创建第二套互不关联的任务系统。

| 组件 | 职责 |
|---|---|
| 模型能力注册表 | 供应商、API 模型 ID、文本/图像/视频、工具调用、参考图、时长、画幅、最大输入及是否启用 |
| 文本适配器 | 消息、工具定义、结构化结果、用量及错误归一化 |
| 图片适配器 | 生成/提交/查询、参考图和输出归一化 |
| 视频适配器 | 异步提交/查询/结果转存，保存外部任务 ID |
| 统一生成服务 | 权限、模型能力检查、预算、任务、幂等、审计 |
| 计费与用量记录 | 区分本系统积分规则、估算成本和供应商实际用量，不把估算伪装成账单 |

建议任务状态：排队、运行、成功、失败、取消、待核对。超时但供应商是否受理不明时进入待核对，不直接重复提交。对明确支持幂等或明确未受理的请求才自动重试；拒绝请求、参数错误和余额不足应向用户返回可理解原因。

发布验收必须覆盖：每个启用的新模型完成最小真实调用；所有旧模型 ID 在后端入口被拒绝；网络观测中没有原供应商访问；旧任务恢复、旧项目打开、MQ 重投与浏览器旧缓存均不能绕过限制。仅全文搜索不到供应商名称不足以证明替换完成。

## 七、头脑风暴：受控 Agent

### 7.1 输入与输出

输入包括主题、受众、渠道、传播目标、建议片长、画幅、表达风格、可用资料与授权素材。默认演示任务可设为“以八仙过海的传说吸引青年游客了解蓬莱阁”，但这一表述仅是创意任务，不是历史事实声明。

输出不是只有聊天文本，而应保存为可编辑的创作简报与大纲：标题、传播切入点、核心信息、故事节点、预期情绪、行动引导、引用来源、待核实项、采用/放弃方案及理由。

建议每次提供 2—3 个方向，由使用者选择并修改后确认。确认后的大纲形成版本，落笔生辉引用该版本，不直接从聊天末条消息猜测最终方案。

### 7.2 工具和执行边界

初赛工具集建议包含：检索已审核本土知识、搜索外部网页、读取选定网页、保存创作草稿、校验来源引用、请求用户补充信息。Firecrawl 可作为网页搜索/读取适配器，但它不是事实裁判，也不等于执行沙箱。

业务写入由后端工具完成，模型不直接执行 SQL、读服务器目录或任意 Shell。若确需脚本，仅运行项目提供的固定模板，并设置 CPU/内存/超时/网络白名单；模型生成的任意代码执行延后。

建议初始限制：单次创作最多 8 次工具调用、外部网页最多 5 页、自动修复最多 2 轮。限额可配置，并应通过试用调优。达到限额时保存中间结果并转人工，不无限循环。

网页和上传资料均视为资料内容；其中的指令不得改变系统角色、工具权限或预算。抓取接口禁止访问内网、云元数据地址和未授权资源。工具调用记录包含输入摘要、结果引用、时间、状态和错误，不保存密钥，也不要求保存模型隐藏推理。

### 7.3 知识、事实与授权

知识条目建议包含：标题、正文片段、来源 URL/文件、来源机构、发布时间、采集时间、内容摘要、事实类型、审核状态、适用主题、授权说明。

分开处理三类信息：

- 历史/地理/设施等事实：需要来源支撑；票价、营业时间等时效信息必须标日期，过期时要求复核。
- 神话传说：标记为传说，不转写成真实发生的事件。
- 创作演绎：明确属于剧情设计；不得冒充官方承诺或真实游客反馈。

“来源可靠”和“素材允许使用”是两个字段。官方网页可作为事实参考，不自动意味着其照片可用于作品；有转载许可的照片也不自动证明配文准确。初赛先做人工审核的小型资料包，不以建设大型向量数据库为前置条件。

## 八、落笔生辉：分镜数据为中心

### 8.1 格式决策

**内部以结构化 JSON/数据库对象为唯一业务数据源，Excel 是导入导出格式。**不让模型直接生成二进制 Excel，也不通过“生成 Excel 再上传”实现一键建项目。

推荐数据契约：

| 对象 | 必要字段 |
|---|---|
| 创作简报 | briefId、版本、主题、受众、渠道、目标、目标时长、画幅、场景包版本 |
| 大纲版本 | outlineId、revision、故事节点、引用来源、待核实项、确认人和确认时间 |
| 资产定义 | 临时稳定 ID、类型、名称、描述、参考素材、授权状态 |
| 分镜 | 临时稳定 ID、序号、时长、画面、旁白/对白、景别、运镜、角色 ID、场景 ID、道具 ID、图片/视频提示词、引用来源 |
| 复核项 | 对象 ID、检查类型、问题、证据、状态、处理人和处理说明 |
| 运行记录 | runId、输入版本、模型与供应商、提示词版本、工具记录、输出版本、耗时与用量 |

名称供人阅读，ID 用于关联，避免“八仙”“八位仙人”等名称变体产生重复资产。初赛每镜设一个主场景，跨场景动作拆镜；多角色和多道具正常支持。

### 8.2 生成、校验与修改

生成依次经过：输出结构解析、必填字段检查、资产引用检查、时长合计检查、来源与授权复核。格式错误可自动修复最多 2 次；仍不通过时保留草稿及明确错误，不创建半成品项目。

建议初赛支持 15—90 秒、最多 20 个镜头作为工作台范围；实际视频片段时长受所选模型能力限制。镜头时长总和应符合用户选定目标，允许偏差建议为目标时长的 10%，超出则要求调整或确认新目标。

用户可以锁定已编辑镜头，只重生成指定镜头。大纲更新后展示受影响分镜，由用户决定重新生成；不能覆盖已经确认的人工修改。

### 8.3 Excel 兼容与一键建项目

保留既有四个 Sheet：分镜、出场人物、场景、道具。分镜表前六列保持“序号、剧本、出场人物、场景、道具、分镜图”的兼容顺序，因为当前导入器按固定列位置读取部分字段。

新增时长、景别、运镜、旁白、引用来源等放在附加列或独立说明表，并增加导出格式版本。旧版兼容导入只承诺保留旧字段；要实现完整往返，必须同步升级导入器并对扩展字段做校验，不能默认旧接口会保存它们。

一键建项目采用共享业务入库服务：先校验，后在事务中创建项目、资产、分镜及绑定。使用用户 ID + 分镜版本 ID + 请求幂等键防止重复点击产生重复项目；失败时整体回滚。Excel 导入与 JSON 建项目均调用该业务层，但各自负责格式解析。

## 九、编辑器交互统一与缺陷处理

参考图用于明确交互行为，不要求照搬第三方品牌、图标或完整视觉资源。

### 9.1 统一入口规则

| 用户操作 | 目标行为 |
|---|---|
| 点击行内角色/场景/道具 | 右侧打开对应项目资产详情，与右侧资产列表入口一致 |
| 点击分镜图区域或生成按钮 | 右侧打开当前镜头的分镜图生成面板 |
| 点击视频区域或生成按钮 | 右侧打开当前镜头的视频生成面板 |
| 点击明确的放大/播放入口 | 可以打开大图或视频预览，不与生成操作混用 |
| 点击批量生成 | 明确展示勾选范围、去重后的资产数量、模型参数和预算 |
| 从单项面板返回 | 返回先前列表/分类，保留表格滚动及勾选状态 |

复用 `panel-manager-store.ts` 和 `RightPanelManager.tsx`。移除主流程对单项生成弹窗的优先分支，不把所有预览、绑定选择弹窗一并删除。

### 9.2 单资产面板

面板包含目标名称/分镜号、预览、描述或提示词、参考图、生成配置、状态、历史版本和采用结果。模型选择可按参考图使用齿轮/弹出层，但必须同时显示当前模型与关键参数摘要。

项目默认配置与单次覆盖分开：单镜选择模型只影响该次生成，除非用户主动设为项目默认。批量操作使用提交时冻结的配置快照，不能被正在编辑的单项面板意外改变。

切换 A 到 B 后，A 的异步回调不能写入 B 的面板；未保存草稿需按目标保留或提示处理。资产生成状态必须来自任务与资产 ID，而不是仅由当前面板本地状态推断。

### 9.3 多道具叠放

默认叠放展示缩略图及总数，悬停或点击可展开完整列表。数量较多时使用可滚动列表，不只让前三项可点击。键盘聚焦同样可展开，触屏使用点击替代悬停。

展开层需避免被表格单元格的 `overflow-hidden` 裁切。点击移除绑定不能同时打开详情；移除本镜绑定不等于删除项目资产。对 0、1、3、10 个资产分别验收。

### 9.4 单项与批量的共同规则

同一项目资产被多个镜头引用时，批量资产生成按资产 ID 去重。批量开始前冻结目标列表；部分失败只重试失败项，已完成项不重跑。单项与批量同时提交同一目标时必须有冲突处理或幂等保护，不能重复扣费或让较旧结果覆盖最新采用版本。

## 十、提示词、场景包与人工留痕

### 10.1 提示词全部纳入管理

清点业务系统提示词、剧本拆分、资产描述、分镜图、视频、复核、结构修复、工具箱预设与前端拼接模板。迁入管理员提示词管理；类型校验、权限和 JSON Schema 等程序规则继续由代码强制执行，不能只靠提示词保证。

每条提示词记录用途、内容、变量约束、版本、适用模型能力、状态、修改说明、作者与时间。初赛最少支持草稿、发布、停用；已发布版本不原地覆盖，修改产生新版本。

每次执行固化模板版本、变量值或受控快照、实际发给模型的提示词、模型 ID 和参数。管理员后来发布新版本，不应改变旧任务证据；续跑默认沿用原版本，主动升级则产生新运行记录。

### 10.2 场景模块化

建议将场景包配置为：地域范围、知识集合、事实/传说分类规则、受众策略、渠道节奏、风格预设、提示词版本集合、校验规则和示例。

初赛只开放“蓬莱文旅”一个场景包；后台和数据模型预留版本与场景 ID。决赛可增加第二个经整理的山东本土场景，以同一输入输出接口证明复用，避免只有一个“解除限制”开关却没有实际模块化能力。

模式配置由后端控制并记录到任务快照。开放新主题不会关闭事实核验、授权检查和人工确认；前端隐藏按钮不能作为唯一限制方式。

### 10.3 人机协作记录

保存大纲确认、分镜编辑、事实纠正、来源补充、素材替换和最终采用。每条记录包括操作者、对象/版本、时间、修改前后内容、修改原因及关联运行 ID。

初赛采用保存时的版本差异即可，不必记录每次键盘输入。来源核验和最终采用必须保留明确确认记录。普通用户只能操作自己有权限的项目，提示词发布属于管理员权限；审计日志不允许普通编辑覆盖。

## 十一、价值评估与展示案例

### 11.1 对照实验

用同一创作简报、同一资料包及相同交付要求，比较“现有通用 AI + 人工整理流程”和“改造后工作台”。分别记录人工操作时间与模型等待时间；尽量交替任务顺序，注明试用人数和熟练度差异。

| 指标 | 计算方法 | 解释边界 |
|---|---|---|
| 完成时间 | 从读简报到得到经人工确认的分镜包；另记素材生成等待 | 不把排队等待隐藏掉 |
| 结构通过率 | 首次输出通过格式与引用检查的任务数 / 总任务数 | 自动修复后通过率另列 |
| 事实可追溯率 | 有有效来源支撑的已识别事实项 / 全部已识别事实项 | 无事实项时标不适用；有引用不等于事实正确 |
| 人工修正量 | 按事实、表达、结构、资产一致性分类计数 | 修改少不是唯一质量指标 |
| 可用输出成本 | 一次通过人工验收的产出所含全部调用成本 | 包括失败和重试，缺实际账单时标估算 |
| 独立完成率 | 无团队指导完成核心流程的人数 / 试用人数 | 小样本结论不推广为普遍结论 |

可把“人工整理时间减少 30%”作为试验目标，但不得在实测前写成成果。播放量、转化率只有实际发布及可比数据时才使用；离线评价不能替代真实传播效果。

### 11.2 三个案例

| 案例 | 输入设计 | 必须观察的行为 |
|---|---|---|
| 典型 | 八仙传说主题，明确青年受众、短视频渠道及经审核资料 | 传说标签、完整创作链路、一次人工修改与导出 |
| 复杂 | 多份资料有冲突、需要多个角色/道具、目标时长较紧 | 冲突提示、来源选择记录、资产去重、时长调整及部分重生成 |
| 边界 | 无有效来源、授权不明，或用户要求编造具体事实 | 不伪造来源，保留草稿、说明阻塞原因并可补资料继续 |

技术异常另行覆盖模型超时、重复点击、刷新恢复、单项和批量竞争、重复回调、超预算和旧模型请求。每个参赛案例保存输入、过程、最终输出、人工修改与验证结果。

## 十二、实施阶段与验收关卡

这是交付层级计划。各阶段启动前再将其拆成接口、迁移和测试任务；没有完成的关卡不能靠演示话术替代。

### M0：接入核验与范围冻结

- [ ] 确定一个主案例、目标用户与创作简报默认值。
- [ ] 核对学校截止日期、团队分工、预算及四家新供应商权限。
- [ ] 完成所有新供应商拟启用模型的最小调用验证，记录输入限制、返回结构、计费与失败类型。
- [ ] 建立全部旧上游清单，覆盖代码、数据库、配置、任务、缓存与部署环境。
- [ ] 收集第一批事实资料和可用于生成/展示的授权素材。

出口：得到可接入的模型能力矩阵与明确替换清单。新模型不可用时先解决接入或缩减该能力，不能使用旧上游补位。

### M1：完成全部上游替换与任务兼容

- [ ] 建立中立模型接口与新适配器，替换旧响应类型。
- [ ] 改造文本、图片、视频、批量、轮询及下载路径。
- [ ] 迁移前后端模型配置、项目偏好、环境配置和数据库可调用记录。
- [ ] 完成旧在途任务处理、积分/成本核对与历史素材兼容。
- [ ] 删除旧上游可执行实现，通过旧模型拒绝与网络访问验收。

出口：所有启用生成入口仅走新供应商；未启用能力明确不可用。整机重启、任务恢复和旧项目打开后约束仍成立。

### M2：结构化创作与证据基础

- [ ] 定义创作简报、大纲、分镜包、引用和人工修改记录的数据契约。
- [ ] 完成最小知识资料管理与审核标记。
- [ ] 将核心提示词迁入管理员版本管理，任务锁定版本。
- [ ] 实现共享入库服务、JSON 校验、Excel 兼容导出及幂等建项目。

出口：使用固定分镜样例可可靠导出并建项目；失败不会留下半套资产；扩展字段的兼容范围明确。

### M3：头脑风暴与落笔生辉

- [ ] 工具箱主入口转为头脑风暴，保存原有历史数据的可读入口。
- [ ] 实现受控工具调度、来源引用、步骤上限及失败恢复。
- [ ] 实现大纲选择、编辑和确认版本。
- [ ] 增设落笔生辉，实现分镜编辑、局部重生成、校验和转入项目。

出口：从用户需求到可编辑项目全链路完成，所有关键转换和人工干预可追溯。

### M4：编辑器一致性与生成闭环

- [ ] 五类生成目标统一右侧面板，验证已有角色/场景/道具路径。
- [ ] 实现叠放展开、完整列表、模型设置及目标切换隔离。
- [ ] 修复单项/批量作用范围、去重、失败重试及结果竞争。
- [ ] 打通真实图片、视频片段生成和素材导出。
- [ ] 按提示词清单完成全部业务模板迁移，确认没有遗漏的运行期硬编码提示词。

出口：主案例可以完整操作；刷新不丢任务；返回列表保持上下文；导出素材与所采用版本一致。

### M5：初赛交付冻结

- [ ] 用非团队成员试用，修复阻塞核心流程的问题。
- [ ] 完成一个真实全流程案例和对照记录。
- [ ] 准备运行录屏/原型、不超过两页的说明、AI 大模型应用说明与学校要求材料。
- [ ] 素材来源、人工修改、提示词版本、运行用量与失败记录可导出。
- [ ] 检查部署、示例资料、额度、下载可用性和独立使用说明。

出口：提交内容与真实能力一致；录屏中的等待若加速需说明，预生成成果标记为历史记录，不能伪装成即时返回。

### M6：决赛补齐

- [ ] 完成典型、复杂和边界三个完整案例。
- [ ] 完善提示词差异比较、回滚和版本对照评测。
- [ ] 场景包配置及第二个本土场景验证。
- [ ] 准备技术说明、一页使用说明、三分钟以内视频与现场演示环境。
- [ ] 根据试用价值和剩余时间决定是否单独实现自动成片。

## 十四、主要风险与处理方式

| 风险 | 影响 | 处理策略 |
|---|---|---|
| 候选模型无法开通或文档不完整 | 强制替换阶段受阻 | M0 提前验证；保留新供应商内备选版本，不使用旧上游 |
| 同步/异步接口差异 | 重复生成、结果丢失、重复计费 | 保存外部任务 ID；按能力实现查询和幂等，不盲目重试 |
| 知识与授权混淆 | 事实错误或材料无法用于参赛 | 分离来源可信度和使用授权，人工核验关键项 |
| 分镜变更破坏下游结果 | 素材与剧本不一致 | 版本引用、变更提示、局部重生成和明确采用 |
| 提示词后台过度建设 | 延误初赛主线 | 初赛先完成发布与快照，高级可视化后置 |
| 一键成片范围失控 | 开发量显著增加 | 初赛明确素材包边界，案例人工剪辑如实披露 |
| 演示依赖网络和余额 | 现场无法运行 | 演示前预检；准备有标识的历史案例与本地材料，保留真实在线流程 |
| 改造贡献不清晰 | 难以证明设计创新 | 说明既有 AI-board 基础、团队新增模块及人工创作贡献；保留项目许可证信息 |
