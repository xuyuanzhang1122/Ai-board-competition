## Tools and checks

The versioned install recipe is `infra/codex-cloud/install.sh`. Its default
tool directory is `$HOME/.local/ai-board-competition`; export
`JAVA_HOME=$HOME/.local/ai-board-competition/opt/jdk-17` and prepend its `bin`
directory to PATH before invoking Maven. Verify both `java -version` and
`javac -version` if a compiler mismatch occurs. Do not change the project POM
to compensate for a mismatched compiler.

Use the Maven settings generated by the recipe under `config/maven-settings.xml`
so dependency requests follow the platform's HTTP proxy. Do not bypass network
policy or alter Docker socket permissions. Installation requires the supported
package-network approval flow. The JDK recipe uses api.adoptium.net and the
official Adoptium GitHub release hosts, in addition to the package-manager hosts.

If the installed toolchain or dependencies are missing, run the install recipe
through the supported setup mechanism. It performs real checks and stops on a
failure. Do not mark an unexecuted recipe as successful. When setup is already
verified, run only checks appropriate to the current code changes.

Frontend entry points after locked installation:

```sh
node node_modules/vitest/vitest.mjs run
node node_modules/typescript/bin/tsc -b --noEmit
node node_modules/typescript/bin/tsc -b
node node_modules/vite/bin/vite.js build
```

Redis and RabbitMQ, and private Spring configuration. Current service startup
has not been verified in this cloud environment. Report that boundary until it
is actually resolved; do not silently substitute the original project's services.

frontend port 3000 and admin port 3001, with the platform-supported preview
binding. Check readiness before reporting success. Generate new development
